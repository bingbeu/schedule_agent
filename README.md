# 热处理排程智能体：校验与事务修订版

保留确定性排程内核、动作 API、CLI/网页三层结构。订单与换规 Excel 原文件保持原样。

## 安装与启动

建议 Python 3.10–3.12。本次验证环境：Python 3.12、pandas 2.2.3、openpyxl 3.1.5。

```powershell
python -m pip install -r requirements.txt
python webui.py --input "data/630厂热处理车间6月排产.xlsx" --no-llm
```

打开 http://127.0.0.1:8787 。Windows 也可双击 `start_june.cmd` 或 `start_april.cmd`。

四月批次：

```powershell
python webui.py --input "data/4月份排产.xlsx" --no-llm
```

CLI：

```powershell
python agent_cli.py --input "data/630厂热处理车间6月排产.xlsx" --no-llm
```

原内核入口也统一使用经过校验的管线：

```powershell
python schedule_heat_treatment_strict_compact.py --input "data/630厂热处理车间6月排产.xlsx" --output "out/june.xlsx"
```

目录含两个历史月份，默认不混合排程。明确需要合并分析时：

```powershell
python webui.py --input data --combine-inputs --no-llm
```

`--rule`、`--tooling`、`--out` 可覆盖目录。原内核对应参数为 `--change-rules`、`--tooling-dir`、`--output`。

## 本次关键修复

- 特殊钢级只读取独立清单的 10 个代码，不再把规则数字、说明和分区号混入清单。
- 21 条换规规则数值保持原样；逗号、分号、且作为 AND，只有显式“或/OR”作为 OR。
- 未命中规则或命中缺失空格数时拒绝接续，不默认为零。
- 计划支数必须是明确的正整数，禁止用吨位替代；多温度试验单列为输入待确认。
- 任务 ID 为“文件名::工作表::Excel行号”；重复合同号不会误操作所有任务，也不会自动去重。
- 贪心接续与后处理都必须满足现有规则；大批量恢复逐组校验，整阶段候选还必须保持人工约束。
- 改动先在副本重排，成功并通过校验后一起提交改动、方案和版本；失败保持原状态。
- 移到末尾是实际位置约束；位置冲突明确返回错误；增加解除锁定与撤销上一步。
- 回火温度修改不新增工序；负数、NaN、Inf、未知任务和非法工具参数会被拒绝。
- 校验首末支时间、数量/节拍、在炉时间、同炉进料间隔和两炉首支衔接，导出再校验。
- 前炉进料延后到回火最早可接料时间，减少订单级模型中的两炉等待。
- 增加有限可行插入恢复，每次最多2000个候选，保持原序列相对顺序和人工约束。
- KPI 按同炉实际前序任务计算，新增前炉、回火炉分别累计空格数。
- 网页保留按会话区分的对话历史；所有修改接口共用操作锁，支持方案版本检查。
- 去掉随后被全排序覆盖的 8 秒 OR 初排调用；主管线无需 OR-Tools。


合同号唯一时可代替任务 ID。若对应多任务，工具会列出 ID，需明确选择。修改温度后列表显示当前值；移除后显示“已移除”。工具 `list_orders` 支持 `offset`、`limit` 分页，网页速查默认显示前 40 条，可通过关键字查找。

离线模式不执行否定句，不部分执行复合指令；请一次发送一条模板指令。延迟动作设置开工偏移，重复调用会替换原设置。多个页面共享同一个本地排程工作台；它们的模型对话历史分开，方案通过版本号与操作锁保护。此版本仅监听本机，不提供多用户权限系统。

## 模型模式

服务地址、模型名、密钥环境变量由 `llm_config.py` 配置。需要使用支持工具调用的模型。示例：

```powershell
$env:DEEPSEEK_API_KEY = "你的密钥"
python webui.py --input "data/630厂热处理车间6月排产.xlsx"
```

不要把密钥写入源码。`python check_model.py` 可作最小连通性检查，计费以服务商为准。预检不证明模型支持全部工具特性。本次没有调用实际模型服务。

## 时间模型与优化范围

时间轴以分钟计，输入步进周期沿用原代码的秒单位。前炉 42 料位、回火炉 70 料位来自当前规则表。超过 20 格的跨温区换规沿用原 `edge_ok` 允许策略，回摆和补前炉限制也沿用原策略。这些策略不等于现场确认表中的独立工艺结论。

订单级模型允许相邻订单按各自节拍计算在炉时间，尚未建模同炉多订单共存时的全炉节拍联动、升降温曲线、输送容量、在制品冻结、真实交期和检修窗口。两炉模型等待为零不是这些设备约束得到证明。正式生产前需现场确认并补充建模。

本版修复正确性并增加有限可行插入，没有宣称求得全局最优，也未新增 CP-SAT。暂缓不代表任务永远不可生产，可以通过合法插入、另开生产批次及明确的跨批次规则继续改进。
